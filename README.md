# NewAPI 中转站一键签到 · Chrome / Edge 扩展

一个运行在 Google Chrome 和 Microsoft Edge 中的 Manifest V3 侧边栏扩展，用于管理多个 NewAPI / 兼容站点，并手动或定时执行签到、领取额度。界面、代码与设计均为本项目原创，不绑定任何具体站点运营方。

> ⚠️ 本项目为**非官方工具**，仅供学习与个人使用。使用前请阅读下方[使用须知与免责声明](#使用须知与免责声明)。

版本更新内容请查看 [CHANGELOG.md](CHANGELOG.md)。
版本更新可以提前导出配置备份；导出不包含登录密码。直接更新源码并重新加载扩展时，无需卸载扩展或重新导入配置。

**源码更新后要重新加载扩展本身**：在 `chrome://extensions/`（Edge 为 `edge://extensions/`）点击此扩展的「重新加载」，确认版本为 **1.7.5**，然后关闭旧侧边栏/管理页并重新打开。只刷新 Agent Router 网页不会更新扩展后台。界面在检测、保存和签到前会核对后台鉴权协议；若仍连到旧后台，将提示重新加载，不会把 Linux DO 错当访问令牌模式。

## 功能

- 在 Chrome / Edge 侧边栏或新标签页管理多个站点；
- 单个平台签到和一键批量签到；
- 支持需要 Cloudflare Turnstile 人机验证的签到站点；
- 支持自定义每日签到时间、浏览器启动补检和签到确认通知；
- 可选择「自动允许一键签到」，到达设定时间后无需再次确认；
- 查看本月签到、额度和 Token 统计；
- 「模型」面板按站点真实流量查看各模型可用性、成功率、平均延迟与平均 TPS（只读，不调用模型、不消耗额度）；
- 卡片上的站点网址可直接点击，在浏览器新标签页打开；
- 支持明 / 暗双主题切换，主题偏好本地记忆；
- 配置仅保存到浏览器 `chrome.storage.local`，不使用扩展服务器或云同步；
- 支持邮箱/用户名密码登录，以及 Agent Router 的 GitHub / Linux DO 重登录签到；
- 支持导入 / 导出本地 JSON 配置。

## 安装

Chrome 和 Edge 使用同一份扩展源码，无需下载不同版本。

### Google Chrome

1. 下载或克隆本仓库。
2. 打开 Chrome 的 `chrome://extensions/`。
3. 开启右上角的「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择本仓库根目录（其中应包含 `manifest.json`）。
5. 将扩展固定到工具栏，点击图标打开侧边栏；也可点击界面中的「展开」进入宽屏管理页。

建议使用 Chrome 116 或更高版本。较旧版本不支持侧边栏时，点击扩展图标会自动打开宽屏管理页。

### Microsoft Edge

1. 下载或克隆本仓库。
2. 打开 Edge 的 `edge://extensions/`。
3. 开启「开发人员模式」。
4. 点击「加载解压缩的扩展」，选择本仓库根目录（其中应包含 `manifest.json`）。
5. 将扩展固定到工具栏，点击图标打开侧边栏；或在管理页点「展开」进入宽屏视图。

建议使用 Edge 116 或更高版本。

## 使用

### 访问令牌模式

添加平台时填写站点首页地址、站点「个人设置」中生成的**系统访问令牌**，以及某些兼容站点要求的 `New-Api-User` 用户 ID。

> 注意：必须是「个人设置」里的**系统访问令牌**，不是「令牌管理」里的 API 令牌（`sk-` 开头）。签到接口只认前者，填错会报令牌无效或权限不足。

令牌只在浏览器本地保存，用于直接请求你配置的站点。**请不要把包含令牌的导出文件提交到 GitHub 或发送给他人。**

### 登录 Cookie 模式

部分站点不允许使用系统访问令牌签到，只允许已登录浏览器会话调用接口：

1. 先在当前使用的 Chrome 或 Edge 中登录目标站点；
2. 添加平台时选择「登录 Cookie」；
3. 扩展会在该站点自己的标签页中发起同源请求，让浏览器自动携带登录会话。

扩展不会读取、拼接或上传 Cookie 字符串。站点的登录状态仍由浏览器和站点自身管理。

### 邮箱密码模式

例如配置 AnyRouter 时：

1. 站点地址填写 `https://anyrouter.top`，鉴权方式选择「邮箱密码」；
2. 填写账号的邮箱或用户名，以及原样登录密码（用户名会去除首尾空格，密码不会）；用户 ID 可选，填写后会核验账号是否一致；
3. 点击「检测连接」。当前会话确认属于此账号时复用会话；需要登录时，扩展打开本站 `/login` 页面，点击「使用邮箱或用户名进行登录」类按钮，填写原生表单并提交；
4. 扩展等待新的登录数据和在线账户接口共同确认登录，不会把“点击登录”当作成功。成功后关闭扩展创建的登录页，后续签到、账户和模型读取复用站点会话；
5. 若密码错误、验证码、二次验证或站点安全验证阻止登录，页面会保留并提示人工处理。完成后重新检测/签到即可，不会自动绕过验证。

### 所有鉴权方式的「仅访问」

添加或编辑平台时，访问令牌、登录 Cookie、邮箱密码、GitHub 和 Linux DO 五种鉴权方式均可开启「仅访问（不调用签到接口）」。它的含义是：**登录、刷新和账户取数照常进行，只跳过签到接口这个动作**。

1. 每次任务新建一个独立临时页，核验当前登录账号；不关闭用户原有页面。
2. 按原有鉴权规则登录：邮箱密码在会话失效或账号不符时通过本站原生表单补登录；原本依赖登录回调的 Agent Router 邮箱密码 / GitHub / Linux DO 任务仍会正常重登录，不因「仅访问」跳过此流程。验证码、二次验证或第三方登录仍需人工完成。
3. 登录确认后，无论复用旧会话还是刚完成登录，都刷新首页一次。
4. 在这一个临时页中读取最新可用额度、已用额度及本月 Token；关闭前再次在线核验账号及额度，并把最新账户信息同步到卡片和本地存储，再关闭临时页。

- **不会要求额度必须上涨才关闭。** 最新额度没有变化或为 0 也是有效结果；缺少额度、登录失效、账号不匹配、加载失败或超时时，保留并激活临时页，不把旧缓存当成最新额度。日志接口不可用时，已确认的最新额度仍可正常更新，本月 Token 显示不可用。
- 检测连接和保存恢复正常登录及账户检测，不再只是校验配置；不会调用签到接口。
- 卡片的「刷新」「模型」以及用户已配置的 API 保活保持正常。开启「仅访问」不再清空或禁用保活设置；保活只有用户原本开启时才按原有任务规则执行。
- Cookie / 访问令牌模式没有自动网页登录凭据时，仍需在打开的本站登录页手动登录。**系统访问令牌不能代替网页登录 Cookie**。配置了用户 ID 时必须匹配；未填写时核验当前浏览器会话。
- 访问结果与签到结果分开保存。卡片显示「仅访问」「今日已访问」，汇总单列「已访问」；即使登录回调包含 `checked_in`，仅访问任务也不会写入签到成功计数。定时访问每天最多完成一次，手动「立即访问」可再次执行。
- 导入/导出保留所有鉴权方式的此选项，但仍不导出或接受导入密码。

这里保证的是**扩展自身跳过签到接口**；网站自身的脚本、登录回调及奖励规则仍由该站点决定。扩展正常读取实际额度变化，但不会据此宣称签到成功或保证奖励到账。

**安全约定：**

- 只支持没有 URL 内嵌凭据的 HTTPS 地址；填写前和提交前都会检查本站 origin、登录路径及表单目标；阻止不安全的原生 GET 提交，避免密码进入 URL；
- 密码只保存到扩展的 `chrome.storage.local`，**不是加密保险箱**。填表时密码会交给你配置的目标站点，本机/浏览器配置被访问时可能泄露，请只添加可信站点；
- **导出 JSON 始终剔除 `loginPassword`**，导入也忽略文件中的密码。导入后必须编辑邮箱密码平台并重新填写密码；
- 导出文件仍可能包含系统访问令牌和保活 API Key，不能公开或发送给他人；
- 非密码模式不向后台传递登录密码。Cookie、邮箱密码和两种 Agent Router 模式启用保活时，必须另外填写 API Key，绝不以登录密码或残留系统令牌代替。

### Agent Router 重登录签到（GitHub / Linux DO）

1. 可以分别添加 GitHub 和 Linux DO 平台配置，填写各自的 Agent Router 数字用户 ID；不要求为了保存第二个账号先手动切换本站会话；
2. 添加平台时按账号登录方式选择「Agent Router（GitHub 重登录签到）」或「Agent Router（Linux DO 重登录签到）」，填写数字用户 ID，**两种方式都不需要访问令牌**；
   「检测连接」和保存不会登出或启动 OAuth。只有在线身份匹配时才显示连接成功并读取此账号额度；当前登录另一账号、尚未登录或正等待授权时，可仅保存配置，明确提示「尚未验证登录」，不复制另一个账号的额度。切换鉴权方式/账号后旧检测结果仍会作废；
3. 点击「立即签到」或「立即访问」，扩展按对应提供方登录；需要重登录时先退出当前站点会话，再打开临时登录页。当前会话可以属于另一个号，不会再在退出前把正常切换拦截为串号；
4. 扩展读取站点 `/api/status` 提供的动态 OAuth client ID，并由本站 `/api/oauth/state?mode=login` 生成登录状态。Linux DO 授权使用 `connect.linux.do`，回调由站点自身 `/oauth/linuxdo` 页面处理，不由扩展兑换授权码；
5. Linux DO 授权页会自动点击 `.oauth-actions a.btn-pill-primary` 中指向本站 `/oauth2/approve/…` 的「允许」链接，仅限扩展本轮创建、`client_id` 和 `state` 匹配的授权页；不会操作其他标签页。其他授权、登录或验证码仍需手动完成。只有观察到本轮对应回调、核验在线账号，且站点登录数据明确返回 `checked_in=true`，才标记「今日已签到」并关闭临时页面。

自动允许在点击前持久化防重复标记。按钮尚未出现且明确没有点击时，后台可再次扫描；若注入结果丢失、无法确定是否已点击，则保留页面供手动处理，不重复提交授权。

打开授权页只是「等待登录」，**不是签到成功**。回调未确认签到、账号不匹配、关闭登录页或等待超过六分钟，都不会新增今日签到标记。等待期间后台会定期复查，因此可接管较慢的回调以及 Service Worker 休眠后的未完成任务。自动/批量统计分别展示成功、已签、失败和等待登录。

旧配置 `authMode=agentrouter_token` 仍代表 GitHub 重登录，不需要重新配置；Linux DO 使用独立的 `authMode=agentrouter_linuxdo`。前后端从同一份 `auth-config.js` 识别这两种模式。不同站点的 OAuth 任务不会互相覆盖/关闭。

**同一站点采用串行切换，不为两个标签页创建独立登录会话。** GitHub / Linux DO 配置可以是不同用户 ID：先完成前一账号的授权及结果保存，再退出本站会话并登录后一账号，各自额度和结果只写入对应配置。前一任务尚未回调时，后一任务会等待，等待超时则提示先完成或关闭原授权页，不抢占会话。重复请求只复用同一个平台、提供方、用户 ID、鉴权方式和任务用途的 pending，不会借用另一账号的登录任务。

回调身份校验使用在线接口，不用旧 localStorage 或缓存额度证明登录。缓存仍是上一账号、但在线身份已正确切换时会继续等待前端更新；在线证明确实登录错号时明确失败并结束该任务，不会挂在「等待登录」或写入错误账号的额度。

### Turnstile 验证签到

部分 NewAPI 站点会在签到接口上启用 Cloudflare Turnstile。扩展检测到「Turnstile token 为空」后，会自动打开或复用目标站点标签页，并在站点页面内显示官方人机验证控件。

用户完成验证后，扩展会自动携带一次性 Turnstile token 提交签到。若标签页由扩展临时创建，会在验证和签到请求完成后自动关闭；用户原本已经打开的站点标签页不会被关闭。

Turnstile 由目标站点和 Cloudflare 提供，扩展不会绕过、伪造或保存验证 token。

### 每日定时签到

开启「定时自动签到」后，可以设置每天的签到时间，例如 08:01：

1. 浏览器在设定时间运行时，扩展会检查当天是否已经执行过一键签到；
2. 如果浏览器当时没有运行，会在当天下一次启动浏览器时补检；
3. 扩展先查询各站点当天的签到状态，只处理尚未签到的平台；
4. 默认通过浏览器通知询问是否允许一键签到，可以选择「允许签到」或「跳过今天」；
5. 开启「自动允许一键签到」后，到达时间会直接执行，无需再次确认。

需要 Turnstile 的站点仍可能打开验证页面等待用户完成验证，无法保证完全无人值守执行。

### 模型可用性面板

在宽屏管理页（点击侧边栏的「展开」进入）中，每张平台卡片会多出一个「模型」按钮，点击后打开模型可用性面板：

1. 面板顶部可切换统计窗口（最近 24 / 72 / 168 小时）、搜索模型名、勾选「仅显示有流量的模型」；
2. 概览表格列出站点支持的全部模型，并显示成功率、平均延迟、平均 TPS 和健康状态；
3. 点击任意一行展开该模型的明细与走势迷你图，再次点击同一行即收起。

数据来源分两种：

- **站点性能指标**（较新 NewAPI 内核提供的 `GET /api/perf-metrics`）：由站点自身按全站真实流量统计，覆盖面最完整；
- **我的调用记录**（站点不支持上面的接口时自动降级）：改用 `GET /api/log/self` 聚合你自己的调用日志，最多采样最近 600 条记录，因此只反映你个人的调用情况。

整个过程全程只读：不会发起任何模型请求，不消耗额度，也不会触发签到。五种鉴权模式都可使用，会话型模式会在站点自己的标签页内发起同源请求。邮箱密码模式在会话失效时可能需要登录；这类站点的登录本身可能附带签到奖励，扩展不会额外发起模型调用。

> 侧边栏窄屏视图不显示「模型」按钮，表格在宽屏下才有足够空间。

### 明 / 暗主题

顶部 / 侧边栏顶部的 ☾ 按钮可切换深色与浅色界面。首次访问跟随系统偏好，之后的选择保存在本地。删除浏览器数据后需重新选择。

## 权限和数据处理

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存平台配置和自动签到设置 |
| `alarms` | 检查每日签到时间、启动补检，以及复查未完成的 OAuth 回调 |
| `notifications` | 显示签到确认和执行结果通知 |
| `tabs` | 打开管理页、复用或创建目标站点验证标签页 |
| `scripting` | 在目标站点内发起同源请求、填写本站登录表单、生成 OAuth 状态及显示 Turnstile 验证 |
| `sidePanel` | 承载 Chrome / Edge 侧边栏界面 |
| `<all_urls>` | 访问用户自行配置的站点接口 |

扩展没有内置的中转服务器、统计服务或云同步逻辑。认证和接口请求发往用户配置的目标站点；选择 OAuth 重登录时会导航至 GitHub 或 Linux DO 授权服务。登录密码不会由扩展发送给这些 OAuth 服务。

## 兼容性与限制

- 主要兼容 NewAPI 的 `/api/user/checkin` 接口及部分兼容实现；
- 不同站点可能修改接口、鉴权方式或签到规则；邮箱密码自动填表主要匹配 NewAPI/Semi UI 登录表单，站点自定义 DOM、原生 GET 表单或二次验证可能需要人工处理；
- Turnstile 验证需要在目标站点页面内完成，站点要求交互时无法完全静默签到；
- 浏览器完全退出时定时任务不会运行，但会在当天再次启动浏览器后补检；
- 模型面板的全站性能指标需要站点使用较新的 NewAPI 内核（提供 `/api/perf-metrics`）；老内核会自动降级为个人调用日志统计；
- 每分钟请求数（RPM）与站点限流配额上游接口未对普通用户开放，因此面板不展示该项；
- 目标站点可能禁止自动化请求，使用前请阅读并遵守其服务条款。
