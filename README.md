# NewAPI 中转站一键签到 · Chrome / Edge 扩展

一个运行在 Google Chrome 和 Microsoft Edge 中的 Manifest V3 侧边栏扩展，用于管理多个 NewAPI / 兼容站点，并手动或定时执行签到、领取额度。界面、代码与设计均为本项目原创，不绑定任何具体站点运营方。

> ⚠️ 本项目为**非官方工具**，仅供学习与个人使用。使用前请阅读下方[使用须知与免责声明](#使用须知与免责声明)。

版本更新内容请查看 [CHANGELOG.md](CHANGELOG.md)。
版本更新可以提前导出配置备份；导出不包含登录密码。直接更新源码并重新加载扩展时，无需卸载扩展或重新导入配置。

**源码更新后要重新加载扩展本身**：在 `chrome://extensions/`（Edge 为 `edge://extensions/`）点击此扩展的「重新加载」，确认版本为 **1.7.14**，然后关闭旧侧边栏/管理页并重新打开。只刷新 Agent Router 网页不会更新扩展后台。界面在检测、保存和签到前会核对后台鉴权协议；若仍连到旧后台，将提示重新加载，不会把 Linux DO 错当访问令牌模式。

## 功能

- 在 Chrome / Edge 侧边栏或新标签页管理多个站点；
- 单个平台签到和一键批量签到；同站点折叠列表可直接快捷签到，访问模式显示「访问」，沿用统一队列与停止控制；
- 进入扩展操作的站点页面时自动关闭公告，优先选择「今日不再显示」；
- 可自定义每次签到/仅访问之间的间隔，默认 60 秒；
- 可终止当前签到并取消排队中的任务；已发往站点的请求无法保证撤回。
- 支持需要 Cloudflare Turnstile 人机验证的签到站点；
- 支持自定义每日签到时间、浏览器启动补检和签到确认通知；
- 可选择「自动允许一键签到」，到达设定时间后无需再次确认；
- 查看本月签到、额度和 Token 统计；提供只读本地历史图表，可按账号或汇总查看最近 7/30 天余额、使用金额和 Token 变化；
- 「模型」面板按站点真实流量查看各模型可用性、成功率、平均延迟与平均 TPS（只读，不调用模型、不消耗额度）；
- 卡片上的站点网址可直接点击，在浏览器新标签页打开；
- 支持明 / 暗双主题切换，主题偏好本地记忆；
- 配置仅保存到浏览器 `chrome.storage.local`，不使用扩展服务器或云同步；
- 支持邮箱/用户名密码登录，以及 Agent Router 的 GitHub / Linux DO 重登录签到；
- 支持导入 / 导出本地 JSON 配置。

## 安装

Chrome 和 Edge 使用同一份扩展源码，无需下载不同版本。

### Google Chrome

1. 下载或克隆本仓库。
2. 打开 Chrome 的 `chrome://extensions/`。
3. 开启右上角的「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择本仓库根目录（其中应包含 `manifest.json`）。
5. 将扩展固定到工具栏，点击图标打开侧边栏；也可点击界面中的「展开」进入宽屏管理页。

建议使用 Chrome 116 或更高版本。较旧版本不支持侧边栏时，点击扩展图标会自动打开宽屏管理页。

### Microsoft Edge

1. 下载或克隆本仓库。
2. 打开 Edge 的 `edge://extensions/`。
3. 开启「开发人员模式」。
4. 点击「加载解压缩的扩展」，选择本仓库根目录（其中应包含 `manifest.json`）。
5. 将扩展固定到工具栏，点击图标打开侧边栏；或在管理页点「展开」进入宽屏视图。

建议使用 Edge 116 或更高版本。

## 使用

### 访问令牌模式

添加平台时填写站点首页地址、站点「个人设置」中生成的**系统访问令牌**，以及某些兼容站点要求的 `New-Api-User` 用户 ID。

> 注意：必须是「个人设置」里的**系统访问令牌**，不是「令牌管理」里的 API 令牌（`sk-` 开头）。签到接口只认前者，填错会报令牌无效或权限不足。

令牌只在浏览器本地保存，用于直接请求你配置的站点。**请不要把包含令牌的导出文件提交到 GitHub 或发送给他人。**

### 登录 Cookie 模式

部分站点不允许使用系统访问令牌签到，只允许已登录浏览器会话调用接口：

1. 先在当前使用的 Chrome 或 Edge 中登录目标站点；
2. 添加平台时选择「登录 Cookie」；
3. 扩展会在该站点自己的标签页中发起同源请求，让浏览器自动携带登录会话。

扩展不会读取、拼接或上传 Cookie 字符串。站点的登录状态仍由浏览器和站点自身管理。

新版 NewAPI（例如 Just）只接受网页会话 Bearer 时，账户读取遇到 HTTP 401 会在本站页面通过 `/api/user/auth/refresh` 换取短期会话令牌，再重试只读账户请求。令牌只留在后台内存，按本轮标签页隔离，不保存到配置、不导出，不以配置的系统访问令牌冒充网页登录。仍须由在线账户接口核验用户 ID；旧内核继续使用原 Cookie 流程。现代会话退出使用 `POST /api/user/auth/logout` 和对应会话 ID，旧内核使用 `GET /api/user/logout`。

### 邮箱密码模式

例如配置 AnyRouter 时：

1. 站点地址填写 `https://anyrouter.top`，鉴权方式选择「邮箱密码」；
2. 填写账号的邮箱或用户名，以及原样登录密码（用户名会去除首尾空格，密码不会）；用户 ID 可选，填写后会核验账号是否一致；
3. 点击「检测连接」。当前会话确认属于此账号时复用会话；需要登录时，扩展打开本站 `/login` 页面，点击「使用邮箱或用户名进行登录」类按钮，填写原生表单并提交；
4. 扩展等待新的登录数据和在线账户接口共同确认登录，不会把“点击登录”当作成功。成功后关闭扩展创建的登录页，后续签到、账户和模型读取复用站点会话；
5. 若密码错误、验证码、二次验证或站点安全验证阻止登录，页面会保留并提示人工处理。完成后重新检测/签到即可，不会自动绕过验证。

### 所有鉴权方式的「仅访问」

添加或编辑平台时，访问令牌、登录 Cookie、邮箱密码、GitHub 和 Linux DO 五种鉴权方式均可开启「仅访问（不调用签到接口）」。它的含义是：**登录、刷新和账户取数照常进行，只跳过签到接口这个动作**。

1. 每次任务新建一个独立临时页，核验当前登录账号；不关闭用户原有页面。
2. 按原有鉴权规则登录：邮箱密码在会话失效或账号不符时通过本站原生表单补登录；原本依赖登录回调的 Agent Router 邮箱密码 / GitHub / Linux DO 任务仍会正常重登录，不因「仅访问」跳过此流程。验证码、二次验证或第三方登录仍需人工完成。
3. 登录确认并等待本站回调导航完成后，在同一个临时页刷新当前页面一次（不使用网页缓存）；仍停留在密码登录页时转到首页。不会先关闭页面、再开新页面取额度。
4. 在这一个临时页中读取可用额度、已用额度及本月 Token；关闭前再次核验账号及额度，并把账户信息同步到卡片和本地存储，再按账号的退出开关清理并关闭临时页。Agent Router 在登录确认后改从刷新后的数据看板读取显示余额，其他站点保持在线接口取数。

- **不会要求额度必须上涨才关闭。** 额度没有变化或为 0 也是有效结果；缺少额度、登录失效、账号不匹配、加载失败或超时时，按退出开关清理并关闭临时页，不从旧缓存额度兜底。日志接口不可用时，已确认的最新额度仍可正常更新，本月 Token 显示不可用。余额首次核验后即保存带时间戳的快照，日志统计最多等待 20 秒；最终核验若失败，保留该快照，并按退出开关清理及关闭临时页，但不标记访问完成。
- 保存只校验本地配置并直接保存，不自动检测账号，也不在令牌输入框失焦时检测；需要时手动点击「检测连接」。检测不会调用签到接口。
- 卡片的「刷新」「模型」以及用户已配置的 API 保活保持正常。开启「仅访问」不再清空或禁用保活设置；保活只有用户原本开启时才按原有任务规则执行。
- Cookie / 访问令牌模式没有自动网页登录凭据时，仍需在打开的本站登录页手动登录。**系统访问令牌不能代替网页登录 Cookie**。配置了用户 ID 时必须匹配；未填写时核验当前浏览器会话。
- 访问结果与签到结果分开保存。卡片显示「仅访问」「今日已访问」，汇总单列「已访问」；即使登录回调包含 `checked_in`，仅访问任务也不会写入签到成功计数。定时访问每天最多完成一次，手动「立即访问」可再次执行。
- 导入/导出保留所有鉴权方式的此选项，但仍不导出或接受导入密码。

这里保证的是**扩展自身跳过签到接口**；网站自身的脚本、登录回调及奖励规则仍由该站点决定。扩展正常读取实际额度变化，但不会据此宣称签到成功或保证奖励到账。

**访问结束后退出账号（可选）：** 在账号的「编辑」窗口开启「仅访问」后，可使用「访问结束后退出账号」开关。每个账号独立保存，默认关闭，旧配置也默认关闭；保存后对后续任务生效，导入/导出保留此选项。

**任务收尾清理：** 默认只关闭本轮临时页、清除扩展内存中的短期令牌，不主动退出网站登录，也不为了退出另开页面。开启上述开关后，访问成功、失败或停止均按站点认证协议尝试退出，再关闭临时页；成功先保存余额，失败或停止保留原始结果。退出失败仍关页并显示警告。只关闭本轮创建的页面，不关闭用户原有页；但开启退出时，同站共享 Cookie 的其他页面也会失去登录态。仅在开启退出且任务页已关闭或在第三方授权站点时，另开本站临时页尝试退出，不操作第三方账号。清理结束才释放同站任务锁。切换账号、密码补登录或 OAuth 重授权前必需的退出不受此开关影响；不主动退出也不能阻止网站自身使会话过期。

**安全约定：**

- 只支持没有 URL 内嵌凭据的 HTTPS 地址；填写前和提交前都会检查本站 origin、登录路径及表单目标；阻止不安全的原生 GET 提交，避免密码进入 URL；
- 密码只保存到扩展的 `chrome.storage.local`，**不是加密保险箱**。填表时密码会交给你配置的目标站点，本机/浏览器配置被访问时可能泄露，请只添加可信站点；
- **导出 JSON 始终剔除 `loginPassword`**，导入也忽略文件中的密码。导入后必须编辑邮箱密码平台并重新填写密码；
- 导出文件仍可能包含系统访问令牌和保活 API Key，不能公开或发送给他人；
- 非密码模式不向后台传递登录密码。Cookie、邮箱密码和两种 Agent Router 模式启用保活时，必须另外填写 API Key，绝不以登录密码或残留系统令牌代替。

### 登录与额度读取进度

账户探测的单次超时与主动停止分开处理：初始登录核验和刷新后的身份/余额核验遇到请求超时，最多尝试 3 次，并仍受等待预算约束；不会因此退出登录、重复刷新或把访问误记为成功。在线身份已确认但登录页尚未完成前端跳转时，会等待页面稳定。按站点策略主动重登录时，进度会明确说明，而不提示为会话失效。

仅访问时会显示打开页面、确认登录、单次刷新、读取余额、统计 Token、最终核验及关闭页面等阶段。HTTP 401 在首次探测时进入登录流程；刷新后再遇 401、权限拒绝、安全验证网页或不兼容的账户数据，会提示具体原因，不再统一空等到 60 秒。网络/权限错误不会直接触发退出旧账号。

登录/导航边界保留公告的 SPA 挂载观察；连续日志请求仍检查新出现的公告，但不再每页重复等待 1.2 秒。页面加载等待支持停止，加载超时不再作为成功继续取数。一次访问仍只安排一次主动刷新/看板导航，保留站点依赖刷新触发奖励的兼容行为。

余额与本月 Token 独立处理：已核验余额先保存，日志统计共用 20 秒预算（最多 40 页），超时或无权限时显示 Token 不可用/部分统计，不丢弃已确认余额。用户主动停止和账号不匹配不能降级成访问成功；关闭前仍须核验账号，失败时保留最近确认快照，并按退出开关清理、关闭本轮临时页。

### 同一 API 地址的多账号折叠

侧边栏和管理页按完整存储快照同步，已删除的余额/错误不会残留。后台用状态版本保护新余额和新结果，较旧页面保存配置不会将其回滚；导入明确重置账号快照。收到任务完成、跨窗口停止或过期进度时立即重绘，避免“处理中”遮住已完成/失败结果。这里的实时更新指扩展任务和已确认快照同步，不表示持续轮询站点余额。

批量任务逐个保存并更新结果，不等待整批结束；“处理中”仅来自当前界面的实际任务，不再保存到账号配置。保活与访问的阶段提示分开，保活请求的 15 秒预算包含响应正文，并响应任务停止。

侧边栏和管理页将相同 API 地址的多个配置折叠到一个站点组，默认显示各账号余额与状态，展开后保留每个账号独立的访问、刷新、编辑、删除按钮。展开状态本地保存并在两个界面同步；单账号保持原卡片展示。

- 地址规范化会忽略尾斜杠和主机名大小写，但保留协议、端口及部署路径，避免合并不同 API 实例。
- 合计按每个账号的额度单位换算；未知余额不算作 0，另行提示。已在线确认相同用户 ID 的重复配置只采用较新的余额快照累计，不自动删除配置。
- 合计是各账号最近确认快照的汇总，不代表同时在线取得；账号卡片显示余额更新时间，旧缓存时间未知时如实标注。
- 展示分组不合并凭据或会话。同站点 Cookie 仍共享，涉及网页登录的账号任务按 origin 串行，包含访问令牌的「仅访问」任务；不会为同时显示余额并发切换登录。

### 快捷签到与本地历史图表

同站点多账号保持折叠时，每个账号的余额旁有独立「签到」快捷按钮；配置为仅访问的账号显示「访问」。按钮调用与展开卡片相同的任务入口，继续遵守全局队列、忙碌保护和「终止签到」，不会展开账号组。

在侧边栏底部或管理页底部打开「图表」，可选择全部账号汇总或单个账号，以及最近 7 天 / 30 天。余额汇总按每个身份的最新快照去重；已用金额只由累计 `used` 的有效非负差分计算，不从余额下降推测消耗；Token 仅比较同一 `YYYY-MM` 内未截断、未回退的连续快照。缺失值、旧快照、跨月、回退及不完整采样会明确标注，不能比较的变化不作推算。

历史只从更新后的真实签到、访问或额度刷新读数开始积累，不追溯补入旧缓存。图表面板只读浏览器本地历史存储，不发网络请求，也不会自动触发签到或访问。首次数据尚未产生时会提示后续操作如何积累样本。

### Agent Router 重登录签到（GitHub / Linux DO）

1. 可以分别添加 GitHub 和 Linux DO 平台配置，填写各自的 Agent Router 数字用户 ID；不要求为了保存第二个账号先手动切换本站会话；
2. 添加平台时按账号登录方式选择「Agent Router（GitHub 重登录签到）」或「Agent Router（Linux DO 重登录签到）」，填写数字用户 ID，**两种方式都不需要访问令牌**；
   「检测连接」和保存不会登出或启动 OAuth。只有在线身份匹配时才显示连接成功并读取此账号额度；当前登录另一账号、尚未登录或正等待授权时，可仅保存配置，明确提示「尚未验证登录」，不复制另一个账号的额度。切换鉴权方式/账号后旧检测结果仍会作废；
3. 点击「立即签到」或「立即访问」，扩展按对应提供方登录；需要重登录时先退出当前站点会话，再打开临时登录页。当前会话可以属于另一个号，不会再在退出前把正常切换拦截为串号；
4. 扩展读取站点 `/api/status` 提供的动态 OAuth client ID，并由本站 `/api/oauth/state?mode=login` 生成登录状态。Linux DO 授权使用 `connect.linux.do`，回调由站点自身 `/oauth/linuxdo` 页面处理，不由扩展兑换授权码；
5. Linux DO 授权页会自动点击 `.oauth-actions a.btn-pill-primary` 中指向本站 `/oauth2/approve/…` 的「允许」链接，仅限扩展本轮创建、`client_id` 和 `state` 匹配的授权页；不会操作其他标签页。其他授权、登录或验证码仍需手动完成。只有观察到本轮对应回调、等待本站完成导航、核验在线账号，且站点登录数据明确返回 `checked_in=true`，才标记「今日已签到」。随后在原临时页刷新一次，读取并保存最新额度和本月 Token，成功后关闭；取数失败保留页面。登录已确认但未获签到确认时也更新可用额度，不误记签到成功。

自动允许在点击前持久化防重复标记。按钮尚未出现且明确没有点击时，后台可再次扫描；若注入结果丢失、无法确定是否已点击，则保留页面供手动处理，不重复提交授权。

打开授权页只是「等待登录」，**不是签到成功**。回调未确认签到、账号不匹配、关闭登录页或超时，都不会新增今日签到标记。同一阶段连续 60 秒没有有效进展时会失败、保留页面并释放队列；可信进展（包括进入新阶段）会重新开始 60 秒计时，同阶段重复或无效响应不会延长等待。等待期间后台会定期复查，因此可接管较慢的回调以及 Service Worker 休眠后的未完成 OAuth 任务。卡片显示登录等待状态，最终自动/批量汇总以回调完成后的成功、已签、已访问或失败结果为准，不再把刚打开授权页算作本项完成。

旧配置 `authMode=agentrouter_token` 仍代表 GitHub 重登录，不需要重新配置；Linux DO 使用独立的 `authMode=agentrouter_linuxdo`。前后端从同一份 `auth-config.js` 识别这两种模式。不同站点的 OAuth 任务不会互相覆盖/关闭。

**所有平台的签到/仅访问共用全局串行队列。** 单站按钮、批量按钮和定时/立即执行的任务按入队顺序逐项执行；不同域名、令牌及 Cookie/OAuth 模式也不并发签到。前一项必须等待登录回调、同页刷新、最新额度取数、结果保存和关页结束，再启动下一项。验证码/授权需要人工处理时队列会等待；同一阶段连续 60 秒没有有效进展会记录失败并释放队列；可信进展（包括进入新阶段）会重新开始 60 秒计时，同阶段重复或无效响应不会延长等待。登录页关闭、配置变化或平台删除也会终止相应旧任务，不强行关闭需要用户处理的页面，也不使用旧账号配置继续登录。后台恢复后，新任务先处理已持久化的 OAuth pending，避免抢占已有登录。

**签到间隔默认 60 秒。** 在侧边栏或宽屏页的设置中修改「签到间隔（秒）」即可即时保存，两种界面会同步设置。支持 0–3600 的整数秒，0 表示不等待；旧配置缺少此字段或值非法时使用 60 秒。第一项没有前置等待，也不会在最后一项结束后空等。间隔从上一项登录/回调、额度取数、结果保存和关页完整结束后计时，失败项结束后也按该间隔执行下一项。

间隔由后台全局队列控制，适用于单站连续点击、手动批量、定时签到、「立即执行一次」及仅访问，不会被另一个窗口的新签到绕过；账户刷新、检测连接、模型读取不增加该等待。新任务执行时读取已保存的间隔，修改值应用于后续进入等待的任务，已开始的本次等待不重新计时。上一项完成时间保存在本地，后台重新唤醒时保留剩余间隔；这不表示完整批次具备断点恢复。等待期间可随时终止，不算作「60 秒无有效进展」，也不向站点发起轮询请求。

侧边栏底部和宽屏「添加平台」按钮左侧均提供「终止签到」。它会停止当前任务并取消排队任务，包括自动签到和仅访问；侧边栏顶部的「导入」入口仍保留。停止操作不会关闭仍需人工处理的登录/验证页面，不会撤销已发送到站点的请求，也不会回滚此前已确认并保存的数据。

**同一站点采用串行切换，不为两个标签页创建独立登录会话。** GitHub / Linux DO 配置可以是不同用户 ID：先完成前一账号的授权及结果保存，再退出本站会话并登录后一账号，各自额度和结果只写入对应配置。前一任务尚未回调时，后一任务会等待，等待超时则提示先完成或关闭原授权页，不抢占会话。重复请求只复用同一个平台、提供方、用户 ID、鉴权方式和任务用途的 pending，不会借用另一账号的登录任务。

回调身份校验使用在线接口，不用旧 localStorage 或缓存额度证明登录。网络失败、HTTP 错误、缺失/非数字用户 ID（包括布尔值 `false`）不能被解释成另一个账号；请求失败时等待并重试，有效数字用户 ID 确实不同才报账号不一致。缓存仍是上一账号、但在线身份已正确切换时会继续等待前端更新；回调刚出现时在线接口也可能短暂返回旧会话，扩展会等待本站完成回调导航并重试，而不是立即报账号不一致。等待后仍确认错号时明确显示当前/配置用户 ID、保留页面并结束该任务，不会写入错误账号额度。

### 账户额度刷新与页面跳转

账户和日志取数遇到刷新/导航导致的页面框架移除时，扩展会在同一个标签页等待加载完成，最多尝试 3 次，不重新打开页面，也不重放签到、登录或授权操作。页面关闭、跳转到其他站点或登录页、账号不匹配，以及权限/接口错误不会盲目重试；加载等待超时后明确提示失败。

卡片将单纯取数失败显示为「额度刷新失败」，与「访问失败」区分。失败时保留之前保存的额度，它不代表本次读取成功；下一次成功读取会清除额度刷新错误，但不会抹去真正的访问/签到失败记录。

### Agent Router 登录后读取看板余额

GitHub / Linux DO（以及 Agent Router Cookie 重登录）完成回调身份核验后，扩展在**同一个本轮标签页**打开 `/console` 数据看板；已经位于看板时硬刷新一次。不在令牌页找余额，也不为余额取数反复请求 `/api/user/self`。

- 从看板可见 DOM 的「当前余额」「历史消耗」及「请求次数」读取数据；等待最多 **5 轮**、每轮间隔 2 秒（最多 4 次间隔）。关闭前再次检查页面账号及余额，保存后才关闭本轮临时页。
- 核对页面显示的用户名与本地登录用户 ID。页面仍在加载、账号不匹配、金额缺失或单位不可识别时，保留页面并明确报错，不从 localStorage 的旧额度字段补数。**可用余额与已用余额同时为 0 时继续等待；5 轮后仍为双零则提示余额未确认、保留页面，不覆盖已有额度或提示余额更新成功。** 这是一条保守规则：真实新账号若两项确实都为 0，也会按未确认处理。
- 将页面美元金额按本站的 `quota_per_unit` 换回原始额度单位，并保留页面显示值及来源标记。额度单位按每个账户分别读取 `quota_per_unit` / `quotaPerUnit`；较旧账户数据未携带单位时兼容使用 500,000，单位或金额无效时显示「—」。混合不同单位的平台会先分别换算，再汇总；不会假设所有站点都使用同一个固定单位。**显示精度以网页为准，通常是两位小数；刷新后的页面显示值也不等于额外经接口核验的实时余额。**
- 本月 Token 仍由原日志接口读取；日志不可用时保留看板余额，并标记 Token 统计不可用。此变更不替代登录回调的在线身份核验，也不绕过网站安全验证；其他站点及手动「刷新」按钮仍保留原接口取数流程。
- Agent Router「仅访问」在登录确认后的额度同步也采用该看板流程，依然跳过签到接口。

### 进入站点时关闭公告

扩展打开或复用站点页面进行登录、签到、仅访问、额度或模型取数时，先检测公告按钮：

1. 优先点击 `data-testid="notice-dialog-close-today"`，即「今日不再显示」；
2. 该按钮不存在、不可见或不可用时，回退至 `data-testid="notice-dialog-close"`；
3. 确认公告消失后再继续后续操作。没有公告时，在短暂的 SPA 挂载检测结束后正常继续；登录导航和刷新后会重新检查。

只操作所配置站点的公告专用按钮，不按普通「关闭」「允许」文字匹配，也不在 GitHub/Linux DO 外站执行此动作。公告点击后仍未关闭时提示手动处理，不重复点击；等待可随签到任务一起终止。普通访问令牌模式直接由后台调用接口、未打开站点页面时，不会仅为公告额外开页。此处理不关闭扩展的签到结果通知，不绕过人机验证，也不把公告关闭视为签到成功。

### Turnstile 验证签到

部分 NewAPI 站点会在签到接口上启用 Cloudflare Turnstile。扩展检测到「Turnstile token 为空」后，会自动打开或复用目标站点标签页，并在站点页面内显示官方人机验证控件。

用户完成验证后，扩展会自动携带一次性 Turnstile token 提交签到。若标签页由扩展临时创建，会在验证和签到请求完成后自动关闭；用户原本已经打开的站点标签页不会被关闭。

Turnstile 由目标站点和 Cloudflare 提供，扩展不会绕过、伪造或保存验证 token。

普通签到完成后后台也会自动读取最新账户额度，单站、批量及自动任务同步到卡片/本地存储。「立即执行」不再在任务关页后额外刷新所有站点，避免重复开页及同站点账号切换后的串号取数。若签到已成功但额度读取失败，会明确提示，不撤销签到结果、不将旧缓存当作新额度。

### 每日定时签到

开启「定时自动签到」后，可以设置每天的签到时间，例如 08:01：

1. 浏览器在设定时间运行时，扩展会检查当天是否已经执行过一键签到；
2. 如果浏览器当时没有运行，会在当天下一次启动浏览器时补检；
3. 扩展先查询各站点当天的签到状态，只处理尚未签到的平台；
4. 默认通过浏览器通知询问是否允许一键签到，可以选择「允许签到」或「跳过今天」；
5. 开启「自动允许一键签到」后，到达时间会直接执行，无需再次确认。

需要 Turnstile 的站点仍可能打开验证页面等待用户完成验证，无法保证完全无人值守执行。

### 模型可用性面板

在宽屏管理页（点击侧边栏的「展开」进入）中，每张平台卡片会多出一个「模型」按钮，点击后打开模型可用性面板：

1. 面板顶部可切换统计窗口（最近 24 / 72 / 168 小时）、搜索模型名、勾选「仅显示有流量的模型」；
2. 概览表格列出站点支持的全部模型，并显示成功率、平均延迟、平均 TPS 和健康状态；
3. 点击任意一行展开该模型的明细与走势迷你图，再次点击同一行即收起。

数据来源分两种：

- **站点性能指标**（较新 NewAPI 内核提供的 `GET /api/perf-metrics`）：由站点自身按全站真实流量统计，覆盖面最完整；
- **我的调用记录**（站点不支持上面的接口时自动降级）：改用 `GET /api/log/self` 聚合你自己的调用日志，最多采样最近 600 条记录，因此只反映你个人的调用情况。

整个过程全程只读：不会发起任何模型请求，不消耗额度，也不会触发签到。五种鉴权模式都可使用，会话型模式会在站点自己的标签页内发起同源请求。邮箱密码模式在会话失效时可能需要登录；这类站点的登录本身可能附带签到奖励，扩展不会额外发起模型调用。

> 侧边栏窄屏视图不显示「模型」按钮，表格在宽屏下才有足够空间。

### 明 / 暗主题

顶部 / 侧边栏顶部的 ☾ 按钮可切换深色与浅色界面。首次访问跟随系统偏好，之后的选择保存在本地。删除浏览器数据后需重新选择。

## 权限和数据处理

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存平台配置和自动签到设置 |
| `alarms` | 检查每日签到时间、启动补检，以及复查未完成的 OAuth 回调 |
| `notifications` | 显示签到确认和执行结果通知 |
| `tabs` | 打开管理页、复用或创建目标站点验证标签页 |
| `scripting` | 在目标站点内发起同源请求、填写本站登录表单、生成 OAuth 状态及显示 Turnstile 验证 |
| `sidePanel` | 承载 Chrome / Edge 侧边栏界面 |
| `<all_urls>` | 访问用户自行配置的站点接口 |

扩展没有内置的中转服务器、统计服务或云同步逻辑。认证和接口请求发往用户配置的目标站点；选择 OAuth 重登录时会导航至 GitHub 或 Linux DO 授权服务。登录密码不会由扩展发送给这些 OAuth 服务。

## 兼容性与限制

- 主要兼容 NewAPI 的 `/api/user/checkin` 接口及部分兼容实现；
- 不同站点可能修改接口、鉴权方式或签到规则；邮箱密码自动填表主要匹配 NewAPI/Semi UI 登录表单，站点自定义 DOM、原生 GET 表单或二次验证可能需要人工处理；
- Turnstile 验证需要在目标站点页面内完成，站点要求交互时无法完全静默签到；
- 浏览器完全退出时定时任务不会运行，但会在当天再次启动浏览器后补检；
- 模型面板的全站性能指标需要站点使用较新的 NewAPI 内核（提供 `/api/perf-metrics`）；老内核会自动降级为个人调用日志统计；
- 每分钟请求数（RPM）与站点限流配额上游接口未对普通用户开放，因此面板不展示该项；
- 目标站点可能禁止自动化请求，使用前请阅读并遵守其服务条款。
